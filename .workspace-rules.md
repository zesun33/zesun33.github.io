# Workspace Rules for Personal Website Development

## 🚨 CRITICAL RULES - MUST FOLLOW

### 1. Prettier Check Before ANY Commit

**ALWAYS run Prettier check and fix before committing:**

```bash
npm run format:check
npm run format  # if needed
```

**Automated Protection:**

- Pre-commit hook automatically runs Prettier check
- If formatting issues found, commit is blocked
- Auto-fixes are applied, requiring re-review and re-commit

### 2. GitHub Push Approval Required

**NEVER push to GitHub without explicit user approval:**

```bash
# ❌ DON'T DO THIS:
git push origin main

# ✅ DO THIS:
npm run pre-push-check  # Verify everything is ready
# THEN ASK USER: "Ready to push these changes to GitHub? (describe changes)"
# ONLY AFTER APPROVAL: git push origin main
```

**Assistant Workflow:**

1. Make all changes locally
2. Run `npm run format:check` and fix any issues
3. Launch local preview (`npm run preview:docker` or `npm run dev`) and verify the changed pages
4. Stage and commit changes
5. **ASK USER FOR PERMISSION** before pushing
6. Clearly describe what will be deployed
7. Only push after explicit user approval

### 3. Pre-Push Checklist

Before requesting push permission, verify:

- [ ] All files are properly formatted (`npm run format:check` passes)
- [ ] Local site was launched and changed pages were smoke-checked (news, publications, projects, etc.)
- [ ] Changes are committed with descriptive messages
- [ ] No sensitive information is included
- [ ] All TODO items are updated appropriately
- [ ] User has reviewed the changes being deployed

**Local preview (Windows / no Ruby on PATH):**

### 4. Emergency Override

If urgent fixes are needed:

1. Still run Prettier check
2. Commit with clear "URGENT:" prefix
3. Ask user for expedited approval with explanation
4. Never skip formatting checks

## 🛠️ Available Commands

```bash
npm run format:check     # Check if files need formatting
npm run format          # Auto-format all files
npm run pre-push-check  # Pre-push verification (Prettier)
npm run preview:docker  # Local site via Docker (Windows-friendly)
npm run dev             # Local site via Ruby/bundle (if installed)
```

## 📋 Workflow Summary

1. **Development**: Make changes, run format:check frequently
2. **Pre-commit**: Husky automatically runs Prettier (or manual check)
3. **Commit**: Descriptive messages, update TODOs
4. **Local preview**: Launch site (`npm run preview:docker` or `npm run dev`) and verify changed pages
5. **Pre-push**: Run pre-push-check, ask user permission
6. **Push**: Only after explicit user approval

---

_These rules ensure code quality, prevent deployment issues, and maintain user control over their repository._
